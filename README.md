# 恐龙 · 找物挑战（网页版）

小程序版（`../miniprogram/`）的浏览器版本：**同一套关卡数据和图片，54 关、690 个物品**，
在电脑和手机浏览器里都能直接玩。

## 一、怎么打开

| 方式 | 命令 / 操作 |
| --- | --- |
| 直接双击（最省事） | 双击 `index.html`，浏览器地址栏会是 `file:///.../web/index.html`，能正常玩 |
| 本地服务（推荐，手机上也好试） | `cd web` → `python -m http.server 8000` → 打开 http://127.0.0.1:8000/ |
| 放到服务器 | 把整个 `web/` 目录传上去即可，纯静态、没有后端、没有构建步骤 |

`file://` 下也能跑，是因为数据是从 `<script src="js/data.js">` 读的（不是 fetch/JSON），
图片全是相对路径的 `<img>`，整个项目里没有一处 XHR。唯一的差别是某些浏览器在 `file://`
下禁用 localStorage，那时进度只在本次打开期间有效，首页会给出提示。

想放到静态托管（OSS / CDN / GitHub Pages 等）就直接传 `web/` 目录，路径全是相对的，不用改配置。

## 二、目录

```
web/
  index.html          首页：封面 + 总进度 + 54 关的关卡格子
  play.html           游戏页：play.html?level=17 这样带关卡号进来
  about.html          玩法说明 + 快捷键 + 清空进度
  css/app.css         全部样式（小程序 app/index/play/about 四个 wxss 的合体）
  js/data.js          关卡数据（由 tools/build-web.py 生成，勿手改）
  js/store.js         进度存储（localStorage，键名和小程序版一致）
  js/util.js          rpx 换算、提示条、确认框、振动
  js/index.js         首页
  js/play.js          游戏页（核心：排版、点击判定、金色高亮、提示、故事、通关）
  js/about.js         说明页
  assets/
    cvr/dino.jpg      封面
    pic/dino/<页号>.jpg   场景大图
    hdr/dino/<页号>.jpg   标题 + 故事
    spr/dino/<页号>.png   精灵图：普通图标 / 已找到图标 / 图中高亮
  tools/build-web.py  从 miniprogram/ 同步关卡数据和图片
```

小程序把图片按分包（`sp1`…`sp8`）打包，那是微信「主包 ≤2MB」的限制逼出来的；
网页没有这个限制，所以这里是平铺的 `assets/pic|hdr|spr/dino/`。

## 三、玩法

和小程序版完全一致：**图画在左上，要找的物品一列排在右侧、一排排在底下**（原书侧栏 + 底栏），
全部物品一眼看全，不需要滑动。

| 操作 | 效果 |
| --- | --- |
| 在图中点物品 | 点对了：图里那个物品变成金黄色，物品栏对应的卡片也变成金黄色 |
| 点错了 | 短振动（手机上）+ 点的位置闪一个红圈（桌面上得看得见） |
| 点「提示」 | 还没找到的物品闪一圈光圈，在光圈处点一下就能过 |
| 点某个卡片 | 只是再报一遍这个物品叫什么（不暴露它在图中的位置） |
| 长按某个卡片 | 弹出「直接算找到」——万一某个热区不准也不会卡关 |
| 点「故事」 | 查看这一关的标题和故事文字（原书扫描） |
| 返回 / 关掉页面 | 进度已经写入浏览器本地，下次进来接着找 |

网页版多出来的东西：

* **键盘**：`H` 提示、`S` 故事、`Esc` 关闭浮层、`Enter` 通关后进下一关。
* **鼠标长按**：按住卡片 0.55 秒（手机上是长按）。

进度存在浏览器的 localStorage（键名 `vc_progress_v1`），**和小程序版的进度不通用**
（一个在微信里，一个在浏览器里），结构和字段是一样的。

## 四、排版是怎么定的

沿用小程序的算法，几条要点：

* **卡片里的图标和图中那个物品一样大（严格 1:1）**：卡片尺寸直接取「物体在图里的显示尺寸」
  （`rect` 乘图画显示尺寸），横竖各自缩放，所以图标正好填满卡片格子、比例和图中一致
  （针就是比骨头小，铅笔就是一条细长条）。放大系数 `E = 1`。
* **侧栏格子按物品的真实高度分配高度**，底栏行高跟着最高的卡片走——等高格子会挤掉高个子物品
  （图一大它们就塞不下，只能被缩小，1:1 就守不住了）。桌面上这个差别很明显。
* **底栏贪心分行**，最多三行，绝不滚动；名称比图标宽时格子跟着变宽，行内按比例分配。
* **图画宽度**：图画越大 → 卡片越大 → 底栏越高 → 可用高度越小，两者互相挤占，
  侧栏那几格还得装得下 1:1 的物品。小程序版固定来回算两遍，宽而矮的窗口上会「缩过头」；
  网页版改成对图画宽度做二分，取「整屏放得下」的最大宽度（同时满足侧栏的高度约束）。

窗口宽度 ≥750px 时 `--rpx` 取 1px（等于小程序的 750 设计稿尺寸），窄屏按比例缩小，
所以手机上和小程序版长得一样，桌面上文字不会跟着屏幕一起放大。内容最大宽度 900px、居中。

## 五、改了关卡数据 / 重新生成了素材之后

```bash
cd web
python tools/build-web.py
```

它会把 `miniprogram/sp1…sp8` 里的图片平铺到 `web/assets/`，并把
`miniprogram/data/dino.js`、`books.js`（`module.exports = {...}`）转成浏览器能直接
`<script>` 加载的 `js/data.js`，最后自检「每关的 pic/hdr/spr 都在、每个物品都有 rect/hot/icon」。
素材本身是用 `../tools/` 里的脚本从 PDF 生成的，见总 README。

关卡数据是用 `<script src="js/data.js?t=…">`（按分钟取时间戳）加载的，
所以**改完数据立刻生效**，不会被浏览器/CDN 的缓存卡住；图片和脚本用 `?v=` 版本号，
换了图就把版本号 +1（`play.html` 里的 `ASSET_V` 和三个页面里的 `?v=`）。

### 某个物品的位置对不上？用 tools/pick.html 手动定位

`tools/pick.html`（线上地址：`https://<你的站点>/tools/pick.html?level=1`）是个坐标拾取工具：

* 上面选关卡，横条里点要改的物品；左下白色小框显示的是它的**卡片图案**（照着在图里找）；
* 在图里**按住拖 → 画一个框**（推荐），或者**点一下 → 把现有框挪到点的位置**，
  再用「缩小/放大 10%」微调；红框是当前位置，灰虚线是其它物品（可关掉）；
* 下面是实时的 `rect: [x, y, w, h]` 和对应图上像素范围，
  点「复制这个 rect」（或改多个物品后点「复制全部改动」）把结果发出来，
  写进 `miniprogram/data/dino.js` 重新构建即可。

手工改过 `rect` 的物品：第 1 关铅笔、针；第 2 关锅铲（2026-09）。

## 六、和小程序版的差异

| | 小程序 | 网页 |
| --- | --- | --- |
| 图片位置 | 按分包打包在包里 | 平铺在 `assets/` 下 |
| 页面 | 每个分包里各有一份 play 页 | 一个 `play.html?level=N` |
| 进度 | `wx.setStorageSync` | `localStorage` |
| 点错的反馈 | 只有短振动 | 振动 + 红圈（桌面没有振动） |
| 关卡图片 | `wx.loadSubpackage` 按需下载 | 浏览器按需加载，不用管 |
| 排版 | 图画宽度来回算两遍 | 图画宽度二分取最大 |
